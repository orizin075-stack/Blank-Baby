# TUKUYO v1022.5 Fusion + claude-patch4（Semantic Soundness / Independent Verification）

外部レビューは、v1022.5 Fusion の問題を次のようにまとめていました。

> 複数の推論器を融合したことで、「同じ読み違いを、作る側と検証する側の両方が承認する」問題が表に出た。

patch4 は、この問題を **構造で止める** ための改良です。patch3 の機能はすべてそのまま残しています。

## 0. レビュー指摘への対応

| 優先度 | 指摘 | patch4 での対応 |
|---|---|---|
| 1 | Semantic coverage accounting | **最終確定の関門を新設**（`semantic_gate.py`）。質問中の数値トークンを全部、証明の中の数で説明できなければ確定しない（`UNCOVERED_NUMERIC_OR_OPERATION`）。2時間30分のような複合量、%、割も 1 つずつ数える |
| 2 | Independent verifier separation | 関門の中に、**作る側とソースを共有しない別の読み取り器（Parser B）** を置いた。producer の答え・証明の再検算・Parser B（または網羅性の監査）の三重条件。Parser B が作る側のモジュールを import しないことをテストで保証 |
| 3 | Multi-operation completeness | 値段の多段操作（%引き、割引き、円引き、値上げ）を全部の段で計算する。別の品物への操作が混ざれば棄権 |
| 4 | Mixed-duration parser | 「2時間30分」「12分30秒」「1L200mL」「3m40cm」を 1 つの量として扱う |
| 5 | Fresh Fusion 100/100 restore | Fusion 配布物そのものに対して、100 サイクルの別プロセス復元ゲートを実行（結果は §5） |
| – | 「箱の数」に中身の総数を答える | 箱を聞く質問に中身の総数を答えたら、関門が止める |
| – | 「走れる」を走った前提にする | 可能形・受け身・使役（走れる／書ける／見られる）や英語の can は、出来事とは別の命題として扱う。混ざれば棄権 |
| – | 無関係な正しい計算を添えると LLM の作り話が verified になる | verified の条件を変更。主張が答えの中で実際に使われていること、答えの中身の語が全部、質問か検算済みの主張で裏付けられていること |

## 1. 最終確定の関門（`src/tukuyo_v1022/semantic_gate.py`）

数の答え（算数・多段推論・仮説・在庫・時間など）は、確定の直前に必ずここを通ります。

1. **網羅性**：質問の数値トークンを全部、証明の中で使った数で説明できるかを確かめます。
   - 説明として認めるのは、同じ値、単位換算した値、割合の係数（20% → 0.8 や 1.2）です。
   - 説明不要として扱うのは、単価を表す「1」（1個120円、1人に）とクラス名（3年2組）だけです。
   - 証明の中に質問文がコピーされていても、それは説明として数えません。
2. **役割**：次の場合は確定しません。
   - 箱を聞いているのに中身の総数を答えた
   - 合計しか分からないのに一部を答えた
   - 別の品物への操作が混ざっている
   - 「予定」「ぐらい」「何個か」のように数がはっきりしない
3. **Parser B**：自前の字句解析で読める型は、自分で値を出して比べます。
   - 対象：速さ×複合時間、値段の多段操作、暦・曜日・時刻、単位換算
   - 違えば確定しません（`INDEPENDENT_PARSER_DISAGREES`）。
   - 一致すれば `independent_parser: AGREE` と記録します。読めない型は `UNDECIDED` と記録し、独立とは言いません。

**「独立」の意味を厳密にしました。**

- `verified-query` の `independent` は、v1014.1 の検証器が一致したときだけ true にします。
- 作る側と同じ系統の再解析（`deliberation_verify`）は「SAME_FAMILY_RECHECK」として、独立には数えません。
- `independence.separate_parser_B` が `AGREE` のときだけ、別に書かれた読み取りが一致したことを意味します。

## 2. 作る側の完全性

- 値段の操作の連鎖を、全部の段で計算するようにしました（`wordprob._ja_sequential_percent` を書き直し）。
  - 例：「2000円を20%引きし、さらに25%引きし、その後10%値上げ」→ **1320**
  - 例：「2割引きにし、そこから500円引き」も扱えます。
  - 操作どうしは「し、さらに」「その後」のような単純な接続でつながっている必要があります。間に別の目的語があれば棄権します。
- 「時速6kmで2時間30分」→ **15**。英語の "for 2 hours and 30 minutes" も同じように扱います。
- 「水が2Lあります。250mL使い、さらに0.5L使いました」→ 1250。「1L200mLあります」も扱えます。

## 3. 論理

- 可能形・受け身・使役が普通の形と同じ命題に混ざったときは棄権します（`POTENTIAL_OR_VOICE_FORM`）。
- 「窓を開ければ」は形容詞ではなく動詞「開ける」として読み、「窓が開いた」（開く）とは別の命題にします。
- 英語の can / could / will などは命題の一部として残します。"Ken can run" と "Ken runs" は別の命題です。"Can a salmon fly?" は "salmon can fly" に並べ替えて照合します。

## 4. LLM の verified

次の 3 つを満たしたときだけ verified にします。

- 検算に通った主張が、答えの中で実際に使われている（計算の値が答えに出てくる、記憶の引用と答えが内容語を共有している）。
- 答えの内容語（漢字・カタカナ語・英単語・数）が全部、質問か、検算に通った主張で裏付けられている。
- 検証できない一般知識（external）に頼っていない。

一部だけ裏付けられていれば `partially_verified` になり、確信度の上限は 0.8 です。

## 6. 全体テスト

- patch4 の全体テストは **413/413 合格**です（Fusion の 403 件と、patch3・patch4 で追加した 10 件）。結果は `evidence_claude_patch4/selftest_patch4_tail.txt` に入っています。
- 系譜試験（4 家系・24 tick）は、継承 12 回、正答 54/54、代謝監査と全体監査ともに合格でした。Fusion と同じ値です。
- 追加したテストは `tests/test_claude_patch4.py` です。内容は次のとおりです。
  - Parser B が作る側のモジュールを import していないこと
  - 部分的な証明や偽の証明を関門が止めること
  - レビューで指摘された事例
  - 可能形の扱い
  - LLM の verified の条件

## 7. 復元ゲート（Fusion 配布物そのもの）

- `tools/recovery_stress.py --cycles 100`（4 家系・3 世代）を、Fusion の配布物（受領書の鍵で検証）に対して別プロセスで実行しました。
- 結果は **100/100 完走**です（所要約 63 分）。毎サイクル、次の 4 つを確認しました。
  - checkpoint 時点と一致している
  - 秘密鍵の hash が変わっていない
  - 資源が保存されている
  - 未来の実行ディレクトリが 0
- 途中で 2 種類の停止注入（`restore:after_txn_marker` と `restore:mid_commit`）も入れ、どちらも合格しました。
- patch4 は復元のコードに触れていません（変えたのは推論・検証・橋渡しだけ）。なので、この結果は patch4 の復元にもそのまま当てはまります。
- 結果は `evidence_claude_patch4/recovery_gate_fusion_report.json` に入っています。
- レビューにあった「workspace で 2 回目の復元に失敗し、未来のファイルが再出現する」問題は、この環境では再現できていません。データ置き場も配布物も、同じ ext4 上にあるためです。
  - 原因を絞るには、問題が起きた保存先のファイルシステムの種類（`df -T`）と、同期ソフトの有無を記録してください。
  - そのうえで、`recovery_stress.py` を `--data` をその保存先に置いて回すのが近道です。

## 8. 限界

- 網羅性の関門は、**作る側が誤って読んだ数を、証明にもっともらしく書き込む**場合は止められません。数が全部使われていても、使い方が誤っていれば通ります。それを止めるのは Parser B が読める型（速さ・値段・暦・換算）だけです。
- Parser B が扱える型は、まだ少ないです。文章題の大半は `UNDECIDED` で、網羅性と役割の監査だけに頼っています。
- 返品・売る・仕入れのような、文脈で意味が変わる動詞は、今までどおり先生から学ぶ領域です（レビューの「24」「50」は今も棄権します）。
- 本物の LLM での効果は、今回も測っていません。
