## 1. V1023r 研究エンジン

### 1.1 世界（`worlds.py`）

- **装置**：スイッチ 5 個（S1〜S5）とランプ 1 個。ランプは隠れた法則に従って点きます。
- **法則の段**：
  - 段 1〜3：手持ちの言葉で書ける法則（全部で 492 通り）。
    - 段 1：単独のスイッチ
    - 段 2：2 個の組（かつ・または・排他）
    - 段 3：3 個の組（全部・どれか・多数決・パリティ・条件分岐）
  - 段 4：**手持ちの言葉の外**。4 個のスイッチで決まるランダムな表です。どの既知の法則とも 6 か所以上違うように作っています。
- **センサー**：実験で読むランプのセンサーは、最大 10% 間違えます（上限だけが子に知らされています）。
- **仕事**：毎回、環境がスイッチ 2 個を固定します。子は残りを決めて仕事をし、本物のランプが点けば報酬が入ります。
- **乱数**：すべて鍵＋カウンタから決めています。あとから環境側で「その時、世界が何と答えたか」を完全に再計算できます。

### 1.2 研究のやり方（`agent.py`）

- **信念**：既知の 492 法則（短い法則ほど事前確率が高い）に加えて、「**言葉の外**（未知の表）」というモデルを常に持ちます。そのため既知の法則が「説明できない何か」に負けることができます。
- **実験の選び方**：期待情報量（bits）が最大の入力を選びます。
- **方法を変える**：「言葉の外」の確率が 0.9 を超えたら、法則探しをやめて、入力ごとの表で覚える方法に切り替えます（`METHOD_CHANGE`）。このとき、食い違った入力を反例として記録します。
- **主張するまでの確認手順**：
  1. 全 32 入力を一度ずつ試す。
  2. 法則と食い違った入力を、もう一度試す。
  3. 環境が選んだ入力で 10 回の再現試験をする。子は、予測を先に出してから結果を見る。
  4. 再現試験で外れた入力を、3 回ずつ試し直す。
  5. どの段階でも、首位の法則が入れ替わるか、確信度が 0.98 を切れば中止。
- **主張の中身**：通ったら `CONFIRMED` として、法則と「新しい試行での一致率の 99% 下限」を主張します。
- **撤回**：確定した法則が、仕事の結果（ノイズなし）と 1 回でも食い違えば撤回します（`REFUTED`）。
- **報告**：毎回の報告には次の項目が入ります。
  - まだ分からないこと
  - 有力な仮説と確信度
  - 次の実験とその情報量
  - 反例
  - 次にやること

### 1.3 研究するかどうかの判断（研究の値段）

研究にはお金（エネルギー）がかかります。だから毎回、損得で決めます。

- **研究の価値** ＝（法則が分かった場合の 1 回あたりの稼ぎ − 今の稼ぎ）× 残りの回数
- **研究の費用** ＝ 必要な実験回数の見込み ×（実験代 ＋ その間に働けない分）

価値が費用を上回るあいだだけ実験します。働くことが今すでに得で、実験と同じくらい情報も得られるなら、働きながら学びます。

主張のための確認は、**お腹がいっぱいの時だけ**します。どこまで満たされていれば確認を始めるかは、Heart が選ぶ気質で変わります。

- **thorough**：上限の半分で始める
- **frugal**：上限の 9 割で始める

### 1.7 本物の代謝につなぐ（`metabolism-init --research-world`、`niche.py`）

探索の台帳とは別に、**本物の代謝の中**にも研究の場所（ニッチ）を作りました。使うかどうかは選べて、既定では使いません。

**しくみ**

- 各家系（家族）のそばに、装置を 1 台置きます。
  - 1 台目の家系はニッチ N0、2 台目は N1、… と順に割り当てます。子は親のニッチに住みます。
  - 同じ seed なら、同じニッチになります。
- 毎 tick、各個体の研究エージェントが「実験・再現試験・仕事・休む」のどれかを提案します。それをその個体の **Heart** が受け入れるか、休むかを選びます。
- エネルギーの出入り：
  - 仕事は、本物のランプが点いたときだけ、共有の貯蔵庫から報酬が入ります。
  - 失敗するとけがになり、エネルギーを燃やします。
  - 実験は、エネルギーを燃やすだけです。
- エネルギーが尽きた個体は、**本物の不可逆な死**を迎えます（organism2）。寿命でも死にます。
- 後継ぎは、親が **確定した（CONFIRMED）法則だけ** を受け継げます。受け継ぐのは公開の知識だけで、learning がオンのときに限ります。
- 受け継いだ法則は、仕事の結果と食い違えば撤回します。
- 研究の状態は、署名つきの代謝の状態に入っています。`metabolism-audit` と `whole-audit` で検証します。

- ニッチの中身（環境側から見た正解）：
  - N0・N1：言葉の外（段 4）
  - N2：段 2、ノイズなし
  - N3：段 1、ノイズ 5%

## 2. Parser B の拡張（`semantic_gate.py`）

patch4 の「別の読み取り器（Parser B）」が読めるのは、速さ・値段の多段操作・暦・換算だけでした。文章題の大半は `UNDECIDED`（独立の確認なし）でした。patch5 では、よく出る型を追加しました。

**追加した型**

- **増減**：食べた・あげた・もらった・降りた・飛んでいった など。意味がはっきりした動詞だけを読みます。
- **値段**：単価×個数（複数の品でも可）と、おつり。
- **等分・配分**：あまり、グループの数も含みます。
- **比較**：〜より多い／少ない、〜倍、ちがい。
- **ある数**：操作が 2 段までの一次方程式。逆にたどって解き、元の式に戻して確かめます。
- **英語の増減**

**作り方の約束**

- 文の切り方・動詞の辞書・質問の読み方は、すべてこのファイルの中で別に書きました。作る側のモジュールは import していません（patch4 のテストがそのまま検査します）。
- 質問の数を**全部自分で使えたときだけ**、値を出します。
- 売る・返品・仕入れ・貸す・釣る のように、文脈で意味が変わる動詞は読みません（`UNDECIDED` のまま）。
- 箱の数を聞く質問には、中身の掛け算を当てはめません。「35人を5人ずつ」は掛け算ではなく、グループ分けとして読みます。

**測った数字**（`think` の経路）

作る側が確定した数の答えのうち、独立に書いた読み取りが一致した（`AGREE`）割合です。

| セット | patch4 | **patch5** |
|---|---|---|
| 未見 E（Parser B を書く前に作った 36 問。sha256 `4a24605b…`） | 3/24 | **12/24** |
| 未見 D | 13/23 | 17/23 |
| 未見 C | 14/30 | 21/30 |
| 合計 | 30/77（39%） | **50/77（65%）** |

- Parser B が止めた正しい答えは 0 件、新しく出た「確信を持った誤り」も 0 件でした。
- 正答数は、全セットで patch4 と同じです（`llm-ask`）。

  | セット | 正答 |
  |---|---|
  | E | 32/36 |
  | D | 42/50 |
  | C | 73/93 |
  | 開発 | 117/138 |
  | A | 58/61 |
  | B | 80/80 |

  Parser B は答えを増やす部品ではありません。確定した答えの**裏付け**を増やす部品なので、正答数が変わらないのは設計どおりです。
- E でまだ `UNDECIDED` の型は次のとおりです。E は評価に使ったので、これらに合わせた手直しはしていません。
  - 1 文に 2 つの出来事が「て」でつながる形（「9人降りて、4人乗りました」）
  - 貯金箱に「入れる」お金
  - 1L500mL のような複合量の増減
  - "gave 7 to Liam"
  - 「〜歳年下」
  - 「〜より何個多い」
  - 「5でわって」
  - 速さから時間を逆算する問題
  - "shared equally among"

## 3. V1022.6 長時間融合試験（`tools/longrun_fusion.py`）

外部レビューの V1022.6 に当たる試験です。

**1 本の試験の中で、ランダムに混ぜて実行する操作**（重みつき）

- 推論：まだ見ていない数で、その場で問題を作る。13 の型があり、棄権すべき問題も含む。
- 教示
- 自習：模擬の先生に聞いてから、新しい数で確かめる。
- 代謝の tick
- checkpoint
- 復元：未来の分岐を進めてから戻し、tick と、覚えた事実が戻ったかを確かめる。
- 停止注入：死亡の直後で SIGKILL する。

**毎回確かめること**

- 操作のたびに `whole-audit`。
- 15 操作ごとに、代謝・LLM・学習の監査も。

| 代謝の tick | 158 | 172 |
| checkpoint ／ 復元 | 46 ／ 32 | 43 ／ 41 |
| 停止注入（実際に止まった回数） | 29（2） | 42（7） |

## 6. 限界

- **研究の世界は小さな箱です。**
  - 入力は 32 通りで、法則の言葉（492 通り）も私が先に用意しました。
  - 言葉の外だと気づいて表に切り替えることはできます。でも、新しい種類の法則を作り出すことはまだできません。
  - 世界も 1 種類（スイッチとランプ）だけです。
- センサーの誤り率の上限（10%）は、子に教えてあります。上限が分からない世界には、まだ対応していません。
- 研究が得になるのは、失敗が痛い世界だけです。失敗が痛くない世界では、試行錯誤だけの子のほうが最後のエネルギーは多くなりました。
- 世界の鍵は、同じデータフォルダの中にあります。子のコードからは触れませんが、OS の権限で分けているわけではありません。
- 文章の読み取りは、今も有限の型です。
  - Parser B が読めない型は、網羅性と役割の監査だけに頼っています。
  - 未見 C の「平均・最小公倍数・面積・数列」は、まだ型がありません。
- 長時間試験の 1 本目（4 時間の予定）は、作業環境の再起動で 65 分で止まりました（§3）。
- 本物の LLM での効果は、今回も測っていません。
