# TUKUYO v1022 + claude-patch1

監査役（Claude）が v1022 に当てた改良パッチです。方針は 1 つだけ。

> **頭のええ外部 LLM を「思考エンジン」として使う。ただし言うたことは全部 TUKUYO 側で検算して、通らんかったら出さへん。**
> **LLM から教わったことは内蔵コアに定着させて、次からは LLM 無しで解けるようにする。**

LLM はコードも状態も書き換えません。LLM の出力は事実として記憶にも入りません。

---

## 1. 何を変えたか

### A. LLM 思考ブリッジ（新規 `src/tukuyo_v1022_llm/bridge.py`）

`llm-ask` の処理順は次のとおりです。

1. **内蔵コアが先に解く。** 証明つきで解けたら `source: local-proof` を返し、LLM は呼びません。
2. 解けんかったときだけ LLM に聞きます。LLM に渡すのは、読み取り専用の範囲に絞った文脈です。
   - 心の状態
   - 魂コア
   - 継承状態
   - 記憶の上位 5 件
   - 学習済みの事実
   - 直近の会話 6 件（`TUKUYO_LLM_SHARE_HISTORY=0` で送らなくできます）
   - `private/` 以下は読みません。
3. LLM には、答えと**主張（claims）**を JSON で返させます。
   - `calc`: 計算式と値。内蔵の安全計算器で検算します。
   - `memory`: 記憶 ID と引用。その ID が実在して、引用が一字一句含まれているかを確かめます。
   - `local`: 内蔵コアで解ける小問。内蔵コアで解き直して照合します。
   - `external`: 検証できない一般知識。「未検証」と明示します。
4. 答えの中に 3 桁以上の数があって、それが主張や質問のどこにも裏付けられてへんかったら、捏造の疑いとして扱います。
5. 検算に落ちたら、検査結果を LLM に返して 1 回だけ直させます。それでもあかんかったら `rejected` にして、**答えは出しません**。
6. 判定は 5 段階です。

   | 判定 | 信頼度の上限 |
   |---|---|
   | `verified` | 0.95 |
   | `partially_verified` | 0.8 |
   | `unverified` | 0.6 |
   | `rejected` | 0（答えは出さない） |
   | `abstained` | 0（答えは出さない） |

7. すべての回答はハッシュ鎖つきで `v1022_llm/ANSWERS.jsonl` に記録します。`llm-audit` で改ざんを検出できます。

チャット（`chat`）は、プロバイダーが設定されていればこのブリッジを通ります。未検証の部分を含む返答には「（一部未検証）」「（未検証）」が付きます。

### B. LLM を「先生」にする（新規 `teacher.py`、`llm-teach`）

内蔵コアが「知らない動詞」「知らない言い回し」で答えを保留した問題について、LLM にラベル付けをさせ、既存の v1022 学習器に渡します。ラベルは次の条件を全部満たしたときだけ採用します。

- ラベルの文面が質問文に実在すること。
- LLM 自身の答えが、自分のラベルから**ローカルで計算し直した値**と一致すること。
- 数字を変えた 2 つ目の問題でも、同じ方向ラベルを返すこと（気まぐれな先生は弾く）。
- 言い換えの場合は、既知の正規形にしか対応づけないこと。候補順を変えた 2 回の呼び出しで一致すること。

採用されたラベルは、既存の学習器のルール（2 種類以上の数値の裏付けが要る）をそのまま通ります。学習のあとは **LLM 無しで**、新しい数字の問題が解けます。

### C. 内蔵コアそのものの強化（LLM 不要）

- **言葉の計算**（新規 `src/tukuyo_v1022/nl_arith.py`）
  - 対応する言い方：「50から13を引くと？」「4の3倍は？」「30の3分の1は？」「6と9を足すと？」「三十たす五は？」「200の15%は？」「What is 12 plus 30?」など。
  - 質問の**全体**が純粋な式に置き換えられたときだけ計算します。「3個と4個を足すと？」のように名詞が残る文は計算せず、保留します。
- **元の v1022 で見つけた不具合の修正**

  | 内容 | 修正前 | 修正後 |
  |---|---|---|
  | 種の言い換え（例：補充しました→補充した）が、学習済みルールを**隠していた** | 5 件で学習が効かへんかった | 修正済み |
  | 「1箱に6個入りが5箱。箱はいくつ？」 | 30 と答えていた | 5 |
  | 「5個ぐらい」「3個か4個」「およそ」「いくつか」 | 正確な数として計算していた（27、25 など） | 保留 |
  | `verified-query` が**別の実体の記憶**を確定扱いで返していた（例：「若葉学院の創立者は？」に「桜台学院の創立者は…」） | 確定扱い | 質問の語が記憶に全部入っていなければ「不確実」 |

- **論理（前件の成立）**
  - 「雨なら地面が濡れる。雨が降っている。」の「雨が降っている」を、前件「雨」の成立として扱うようにしました。
  - 前件として認めるのは、閉じたリストの発生述語（降っている、吹いた、起きた、発生した、続いている など）だけです。
  - 「雨が降った夢を見た」「雨が降ると聞いた」「雨雲が見える」は成立扱いにしません。
- **独立検証**（`src/tukuyo_v1005/verifier.py`）
  - 内蔵コアが出した答えを、別に書かれた v1014.1 の意味検証器で読み直します。
  - 両者が決着して食い違ったら、答えを保留します。
  - 「地面は濡れるです。」と「地面が濡れる」のような表記ゆれは同じ命題として扱います。

### D. 代謝の恒常性（`src/tukuyo_v1022/metabolism.py`）

- 行動の選び方を「好奇心まかせ」から「期待されるエネルギー収支と満腹の基準点（8000）」に変えました。お腹が空いたら働き、満ちたら休みます。
- たまに試し打ちをして、成功率の推定が固まらないようにしています。試し打ちの結果は心のフィードバックには入れません。

## 2. 測った数字（このパッチ環境、LLM なし、元の v1022 と同じ機械・同じ日に比較）

### 全体テスト

- クリーンなコピーにパッチ用の信頼アンカーを指定して実行し、**334/334 が通りました**。
- 内訳は既存のテスト 326 件と、このパッチで追加した 8 件です。
- 元の v1022 で落ちていた v1014 系のテストも、このパッチでは通ります。

### 内蔵コアだけでの比較

対象は 162 問です。内訳は `tools/llm_eval_sets.json` の 130 問、曖昧な在庫問題 9 問、回帰確認 2 問、パッチ作成**後**に新しく書いた未見問題 21 問です。

| 指標 | 元の v1022 | patch1 |
|---|---|---|
| `verified-query` で**間違ってるのに確定扱い** | 15 件 | **1 件**（下の注を参照） |
| `verified-query` の正解（正しい保留を含む） | 64 | **91** |
| 言葉の計算（開発用 20 問、`think`） | 0/20 | 20/20 |
| 言葉の計算（**作成後に書いた未見 30 問**） | — | 27 正解、3 保留、**誤答 0** |

数字の注：

- 「間違ってるのに確定扱い」の 15 件は、採点スクリプトが拾った 17 件から 2 件を除いた数です。除いた 2 件は「9.0」を「9」と別物と数えた採点上の誤判定です。
- patch1 に残る 1 件は「3個食べるつもりでした。残りは？」→ 32 です。食べてへんので、32 は妥当な答えやと思います。
- 未見 30 問の保留 3 件の内訳は次のとおりです。
  - 2 の 10 乗：内蔵計算器の安全上限が 8 乗までのため。
  - 「8の半分」：この言い方に未対応のため。
- 引き換えに失ったもの：言い換えの記憶質問が 1 問、確定から保留に変わりました（「蒼月山の**高さ**は？」と「標高」）。言い換えは LLM 先生（alias 学習）で補う設計です。

### LLM の部分について（重要）

**この環境からは本物の LLM に接続できませんでした。** そのため LLM まわりは、決定論的なスタンドイン（`tools/mock_llm_provider.py`）で「配管と安全装置」だけを試験しています。

| モック | 結果 |
|---|---|
| 正直 | 計算は `verified`、記憶は `verified`、一般知識は `unverified`（0.6、不確実の印つき）、知らない質問は `abstained` |
| 計算をごまかす | 2 回とも検算に落ちて `rejected`。答えは出さない |
| 記憶 ID を捏造する | `rejected` |
| 気まぐれな先生 | 2/2 とも却下され、何も学習しない |
| 正直な先生 | 2/2 学習。そのあと LLM 無しで新しい数字の問題に正解（31、41）。未学習の動詞（譲りました）は保留のまま |

**本物の LLM で賢さがどれだけ上がるかは、まだ測っていません。** 次の節の方法で、お手元のキーを使って測ってください。

## 3. 使い方

### Claude API を使う場合

```bash
export TUKUYO_LLM_PROVIDER=anthropic
export ANTHROPIC_API_KEY=sk-ant-...
export TUKUYO_LLM_MODEL=<モデルID>   # 例: claude-sonnet-5 。最新の ID は https://docs.claude.com/en/docs/about-claude/models を確認
```

### ローカル LLM（Ollama、LM Studio、vLLM など OpenAI 互換のもの）を使う場合

```bash
export TUKUYO_LLM_PROVIDER=openai
export TUKUYO_LLM_BASE_URL=http://localhost:11434/v1
export TUKUYO_LLM_MODEL=qwen2.5:14b   # 例
```

### コマンド

```bash
T=../deliverables/TUKUYO_v1022_TRUST_ANCHOR.txt     # このパッチの信頼アンカー
python3 run_tukuyo.py --runtime-trust-file $T --data D llm-status
python3 run_tukuyo.py --runtime-trust-file $T --data D llm-ask "質問"
python3 run_tukuyo.py --runtime-trust-file $T --data D llm-teach questions.json   # {"questions":[...]}
python3 run_tukuyo.py --runtime-trust-file $T --data D llm-audit
python3 run_tukuyo.py --runtime-trust-file $T --data D chat
```

### 本物の LLM での効果測定

```bash
python3 -B tools/llm_eval.py --trust-file $T --out result.json
```

同じ問題を「内蔵コアだけ」と「LLM あり」で解かせて、セットごとに次の 3 つを出します。

- 正解
- 間違ってるのに確定扱い
- 保留

**見るべきなのは「正解」が増えたかどうかより、「間違ってるのに確定扱い」が増えてへんかどうか**です。

## 5. 安全上の境界

- LLM はコード、状態、記憶、心、魂のどれも書き換えません。書き換えは既存の監査つき経路を通る「学習」だけです。しかもラベルはローカルで再計算した値と一致したものに限ります。
- LLM の答えは「事実」として保存しません。
- 検証できない主張は「未検証」と表示し、信頼度の上限を 0.6 にしています。
- API キーは環境変数から読むだけです。ディスク、ログ、出力のどれにも残しません。
- LLM に送る文脈の範囲は §1-A のとおりです。会話履歴を送りたくない場合は `TUKUYO_LLM_SHARE_HISTORY=0` を設定してください。

## 6. 限界（正直に）

- **一貫して間違う先生は見抜けません。** 自分の中で辻褄の合う誤りは、全部のチェックを通ってしまいます。大事な分野では複数のモデルを先生にしてください（`claim_boundary.consistently_wrong_teacher_detectable: false`）。
- `external` の主張（一般知識）は検証できません。「未検証」と表示するだけです。
- 内蔵コアの賢さは、今も**狭い型の問題**に限られます。在庫算、言葉の計算、単純な論理、記憶の照合です。一般的な文章題（例：「時速5kmで4時間」）は LLM 頼みです。
- 開発中、私の「第二意見」機能が、元のコアがわざと保留していた曖昧な問題 3 つ（「3〜5個」など）を確定で答えてしまいました。既存のテストがこれを捕まえたので、「型が無くて答えられへん」場合にだけ使うよう制限しました。**別々に書かれた検証器 2 つでも、同じ盲点を共有することがある**という教訓です。
- 代謝の閉じた経済では、学習が生存の得になりません。再生や競争を入れない限り、ここは変わりません。
