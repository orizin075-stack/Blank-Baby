# TUKUYO v1020.1 デバッグ修正版

v1020の集団生態系モデルに対する修正。配布版とrelease_revisionはv1020.1、集団データのモジュール・schema・コマンドはv1020のまま。基本的な起動と実験はREADME_V1020.mdを参照する。外部公開鍵にはTUKUYO_v1020_1_TRUST_ANCHOR.txtを使う。

## 確認して修正した不具合

1. 履歴末尾とキャッシュを同時に古い状態へ戻すと、両者の一致だけで集団監査を通り、更新が古い履歴を継続して全体状態を再署名していた。現在は既存キャッシュ・欠落キャッシュとも、最後の署名付き全体状態に記録された集団ハッシュへ毎回照合する。署名、schema、個体identity、集団ハッシュが欠ける場合も拒否する。失敗時にはデータを書き換えない。
2. 浮動小数点の許容誤差により、資質の総量が3.15より0.000001少ない署名付き出典を受理していた。現在は資質を百万分の一の整数単位として検査し、合計3150000を要求する。変異でも同じ検査を使う。

全体データと鍵を丸ごと以前の版に戻した場合を検出する外部の単調カウンターは実装していない。今回の修正は、最新の署名付き全体状態が残っているのに集団の履歴とキャッシュだけが古くなるケースを防ぐ。

3. 復旧処理は対象ファイル自身のリンクだけを検査しており、親ディレクトリのリンクを通してデータ領域外へ書き込めた。現在は復旧・ステージ作成の前にデータ内のリンクを拒否し、復旧書込みの対象では各親も検査する。明示的な外部出力先は別扱い。競合する悪意あるプロセスとのリンク差替え競争への耐性は保証しない。

## 複数プロセスの再現手段

比較スクリプトに `--execution-mode subprocess_cli` を追加した。指定すると初期化・参加・更新・監査をそれぞれ新しいCLIプロセスで実行する。既存の `in_process_cli` 方式も残す。公開結果の保存は一時ファイルから置換し、その場で読み戻しを照合する。

```sh
python -B tools/population_campaign.py --runtime-trust-file ../TUKUYO_v1020_1_TRUST_ANCHOR.txt --out-dir ../campaign-new --ticks 64 --execution-mode subprocess_cli
```

出力先は新規ディレクトリを指定する。実験の秘密鍵を含む個体データは公開しない。

## 未解決の観測

前版の初期試行で起きた、キャッシュが古い内容へ戻る観測と検査出力が0bytesになる観測の根本原因は未確定。今回の2件の修正がそれらの原因を解消したとは主張しない。書込みと出力の確認は防御であり、保存後の永久的な不変性を保証しない。不一致が出た場合はデータを保全し、署名付き全体状態を勝手に再作成して検査を通さない。

モデルの子は実個体の後継ではない。自然選択・一般L5・意識・24時間連続運用の成立を示す版ではない。並行する旧機能の書込み、Windows/macOS、実電源断、第三者の再現は未検証。
