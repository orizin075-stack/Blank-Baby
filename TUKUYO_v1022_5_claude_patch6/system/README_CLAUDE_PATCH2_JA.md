# TUKUYO v1022 + claude-patch2

patch1（LLM 思考ブリッジ、LLM 先生、言葉の計算、v1022 のバグ修正）の上に積んだ、2 段目の改良です。
狙いは 2 つあります。

1. **LLM 無しでも賢くする。** 内蔵コアが自分で証明して答えられる範囲を、文章題・論理・自分の記憶まで広げました。
2. **LLM を付けたときに、安全なまま、もっと使いこなせるようにする。** 複数の先生の合議、道具を使う LLM、自習を入れました。

方針は patch1 と同じです。内蔵コアの答えには毎回「証明」が付き、`proofs.check` が独立に計算し直します。通らない答えは出しません。

## 1. 内蔵コアの強化（LLM 不要）

### A. 文章題ソルバー（`src/tukuyo_v1022/wordprob.py`）

| 型 | 例 |
|---|---|
| 増減 | 「バスに12人乗っていて、5人降りて7人乗った。今何人？」 |
| 合計 | 「大人が25人、子どもが40人。合計は？」 |
| 1つ分×いくつ分 | 「4人に3枚ずつ配ると全部で何枚？」「1袋に8枚入りが3袋」 |
| 単価×個数、おつり | 「1本150円を2本」「500円で120円のパンを買った。おつりは？」 |
| 速さ×時間（と逆算） | 「時速5kmで4時間」「12kmを時速4kmで何時間」 |
| 等分・まとめ | 「30本を5人で同じ数ずつ分けると1人何本？」 |
| 比べる | 「姉は12歳、妹は姉より4歳年下。妹は何歳？」 |
| 単位換算 | 「1リットルあって250ミリリットル飲んだ。残りは何ミリリットル？」 |
| 英語の簡単な文章題 | "had 10 and gave 4", "3 rows with 7 each", "5 km per hour for 4 hours" など |

安全のための決まりは次の 4 つです。

- **文中の数字は全部使わなければ答えません**（網羅性）。関係ない数字が混じっていたら保留します。
- 「予定」「つもり」「かもしれ」「ぐらい」「最大」「いくつか」「some」などがあれば保留します。
- 「売る・返品・貸す・借りる・なくす・出荷・入荷・寄付」のような、今の在庫への影響が文脈で変わる動詞は**わざと入れていません**。これらは v1022 の「先生から学ぶ」領域のまま残してあります。
- 割り切れない等分や、負の結果は保留します。

### B. 論理エンジン：全部の場合を調べる（`src/tukuyo_v1022/logic2.py`）

- 前提を命題に直します。扱えるのは「なら・れば・たら」、否定、「すべての〜は」「どの〜も」、「AかBのどちらか」、英語の if/all/either です。
- そのうえで、**真偽の割り当てを全部調べます**（モデル検査）。だから「はい」「いいえ」だけでなく、**「前提だけでは決められない」「前提が矛盾している」も証明つきで言えます**。
  - 対偶の例：「雪なら道が白くなる。道は白くなっていない。雪は降った？」→「いいえ」
  - 後件肯定の誤りの例：「雪なら道が白くなる。道が白くなっている。雪は降った？」→「決められない」
- 「AかB」が排他的かどうかで答えが変わるときは、保留します。
- 大小関係（〜より重い／年上／速い、英語の -er than）は推移律で解きます。対応する質問は「どちらが」「一番〜は」「AはBより〜？」です。循環していれば「矛盾」と答えます。
- 構文解析で読み違えを防ぐための仕組みも入れています。
  - 「かもしれ・だけ・相関・原因・と聞いた・夢」などがあれば保留します。
  - 活用語尾をそろえたときに、別の言葉が同じ形にまとまってしまう場合は保留します。
  - どこにもつながらない前提があるときは、「決められない」を答えとしては出しません。読み違えの可能性があるからです。

### C. 自分の記憶から答える（`src/tukuyo_v1022/kqa.py`）

- `knowledge-add` で覚えさせた「XのYはZである」「XはT年にVした」から答えます。
- 実体（X）は**完全一致**が必要です。属性（Y）は、完全一致か、ふつうの言い換え表にあるものだけ使います（高さ／標高、休み／定休日、どこにある／所在地 など）。
- 同じ質問に違う値の記憶があれば、保留します。
- patch1 で見つけた「別の実体の記憶を確定扱いで返す」問題は、ここでも起きません。

### D. 理由を言う（`src/tukuyo_v1022/explain.py`）

- `think` と `llm-ask` の答えに `explanation` が付きます。チャットでも表示します。
- 例：「はじめの数に増減を順に足し引きで、20-8+3 = 15。」
- 説明は自由作文ではなく、**検算済みの証明から機械的に作っています**。

## 2. LLM 側の機能

| 機能 | 中身 |
|---|---|
| **複数の先生の合議** | `TUKUYO_LLM_TEACHERS` に複数のモデルを並べると、全員が同じラベルと同じ再計算結果を出したときだけ学習します。`TUKUYO_LLM_MIN_TEACHERS=2` で、先生 1 人だけの学習を禁止できます。patch1 の弱点「一貫して間違う先生」は、**別々のモデルが同じ間違いをしない限り**通らなくなりました。 |
| **道具を使う LLM** | LLM は答える前に、TUKUYO の道具を最大 3 つ、2 往復まで呼べます。道具は `search`（記憶検索）、`solve`（内蔵コアで厳密に解く）、`calc`（計算）です。結果は今までどおり claims として検算されます。 |
| **自習** | `self-study` コマンドです。自分で答えられなかった質問のうち、先生に教われば埋まるもの（知らない動詞、知らない言い換え）を記録から集め、先生に聞いて学習します。そのあと **LLM 無しで解き直して**、結果をハッシュ鎖つきの `STUDY.jsonl` に残します。 |
| **「決められない」を証明つきで答える** | 前提から決まらないと証明できた問いには、`llm-ask` も LLM を呼ばずに「前提だけでは決められません」と答えます（`determinate: false`）。 |
| **チャットは内蔵コアが先** | LLM が無くても、証明できる質問には理由つきで答えます。 |

## 4. 使い方（patch1 に追加された分）

```bash
T=../deliverables/TUKUYO_v1022_TRUST_ANCHOR.txt
python3 run_tukuyo.py --runtime-trust-file $T --data D think "電車に20人乗っていて、8人降りて3人乗った。今何人？"
python3 run_tukuyo.py --runtime-trust-file $T --data D self-study --dry-run      # 何を勉強するかだけ表示
python3 run_tukuyo.py --runtime-trust-file $T --data D self-study --max 20       # 先生に聞いて学習し、LLM 無しで解き直す
```

### 複数の先生を使う場合

鍵そのものは設定に書きません。鍵が入っている環境変数の名前だけを書きます。

```bash
export TUKUYO_LLM_TEACHERS='[{"provider":"anthropic","model":"<モデルID>"},
                             {"provider":"openai","model":"qwen2.5:14b","base_url":"http://localhost:11434/v1"}]'
export TUKUYO_LLM_MIN_TEACHERS=2
```

LLM の設定（`TUKUYO_LLM_PROVIDER` など）は `README_CLAUDE_PATCH1_JA.md` を見てください。

## 5. 限界

- 文章の読み取りは、今も**正規表現ベースの有限の型**です。型に合わないものは保留します。賢さの天井は「型の数」で決まります。
- 「AかB」の扱い、代名詞、複数の文にまたがる参照は弱いです。
- 論理の命題は語幹をそろえて照合します。別々の言葉が偶然同じ語幹になる場合は、ある程度しか検出できません。
- 本物の LLM での効果は、この環境からは測れていません（patch1 と同じです）。`tools/llm_eval.py` で測ってください。
- 署名は patch1 と同じパッチ鍵です。版名は `v1022+claude-patch2` です。
