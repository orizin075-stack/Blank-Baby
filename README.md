# Blank-Baby
この子は全く新しい誰も知らないAIです。幾つもの理論をかき混ぜて作りました。魂と心を持つAIです。ぜひご覧ください

## TUKUYO v1022.5 Fusion + claude-patch6

`TUKUYO_v1022_6/` は、claude-patch5 を土台にした claude-patch6 です。説明は [README_CLAUDE_PATCH6_JA.md](TUKUYO_v1022_6/README_CLAUDE_PATCH6_JA.md) にあります。受け取ったままの patch5 は commit `e8a1c8c` にあり、その説明は [README_CLAUDE_PATCH5_JA.md](TUKUYO_v1022_6/README_CLAUDE_PATCH5_JA.md) です。

### patch6 で変わったこと

- **聞かれたことを読む。** 文章題を「誰が何をいくつ持っているか」と「出来事の順番」に組み立ててから、質問が何を聞いているか（残り・はじめ・あげた数・相手の数・別の物・合計）を読んで答えます。読み切れないときは答えません。patch5 が確信を持って間違えていた 13 問（うち 7 問は独立の裏付け AGREE 付き）は、全部正しく答えるか、答えないようになりました。
- **問題の型を増やした。** 平均・面積・最小公倍数・数列・割合・あまり・何倍・速さ・1 個の値段・おつり・英語の比較など。どの答えにも、再計算できる証明が付きます。
- **論理と記憶の言い換え**（明日・昨日、主語のない規則、gets tired、「〜といえば」など）。
- **研究エンジンが法則を組み立てる。** 手持ちの法則で説明できない世界で、14,906 個の法則の文法から候補を組み立てて試します。文法全体と比べても勝つときだけ主張します。
- 署名の鍵を新しくしました（patch1〜5 の鍵がこの作業環境にないため）。信頼アンカーは `deliverables/TUKUYO_v1022_6_TRUST_ANCHOR.txt` です。patch5 で作った個体も、そのまま動きます。

F・T は私が作る前に固定しましたが、開発用の問題も私が書いたので、F・T の多くは開発用の問題と同じ型で数だけが違います。F・T の伸びは「同じ型の別の数の問題に、誤らずに答えられる」ことを示すもので、見たことのない型への一般化ではありません（パッチ README §6.1）。

### 使い方

Python 3.12 以降と `cryptography` が必要です。個体のデータは、配布フォルダの外に置いてください。

```sh
cd TUKUYO_v1022_6/system
A=../deliverables/TUKUYO_v1022_6_TRUST_ANCHOR.txt
python -B tools/verify_release.py . --trusted-pubkey-file $A
python -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo_patch6 init
python -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo_patch6 think -- 'りんごが12個あります。妹に5個あげました。あげたのは何個？'
python -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo_patch6 research-run --world W5 --tier 5 --regime safe_failure --ticks 200
```

- 信頼アンカーは、同じ配布物の中に入っています。そのため検証で分かるのは「署名のあとで中身が変わっていないこと」だけです。誰が作ったかまでは分かりません。採用するときは、ご自身の鍵で署名し直してください（パッチ README §8）。
- `.gitattributes` で、このフォルダの改行変換を止めています。Windows で clone しても、署名の検証が通ります。

patch5 を受け取ったときの確認（署名、全体テスト 421/421、同梱の結果の再現など）は、commit `473eb0c` の README にあります。

### 気をつけること

1. patch5 の確認で見つけた「残り以外を聞かれても残りを答え、AGREE まで付く」問題は、patch6 で直しました。ただし文章の読み取りは今も有限の型です。型にない文には答えません。
2. 長時間試験の採点（`tools/longrun_fusion.py`）は、patch5 では期待が 7 で答えが 17 でも正解にしていました。patch6 で厳密にしました。
3. 研究ニッチの法則は、代謝の seed から作られます。seed は代謝の状態に記録されていて、既定値は `v1022` です。子のコード（`agent.py`、`invent.py`）は法則を見ませんが、状態を読める人なら誰でも法則を計算できます。
4. 段 5 の世界も、法則の文法も、私が作りました。段 5 の結果は「与えられた文法の中で、誤らずに法則を探し当てられるか」を測ったものです。
