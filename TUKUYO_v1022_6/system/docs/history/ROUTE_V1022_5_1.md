# V1022.5.1 — Semantic stabilization

V1022.5から有限文章題の意味検証とLLM回答の根拠束縛を修正した実験版です。V1023への昇格ではありません。

## 確定までの条件

1. Producerが候補とproofを生成する。
2. Proof checkerが形式計算・推論を再実行する。
3. stdlibだけを使う `semantic_coverage.py` が、対応する型について原入力を別に読み、数値の出現位置、単位、対象、操作数を照合する。
4. 別入力グラフと候補が一致しない場合、`think` も `verified-query` も確定しない。

対応した独立入力型は、日本語の価格操作・混合時間/速度、英語の容器と内容の対象、日本語の明示的な容器数です。能力・願望を出来事として使う論理推論、単位の異なる比較、不均等配分、負の個数も拒否します。期間に続く述語も検査し、休憩・停車・睡眠などを移動時間として扱いません。未対応型は `OUTSIDE_INDEPENDENT_INPUT_SCHEMAS` と記録します。自然言語意味検証全体の独立性や完全性を主張しません。学習した未知動詞の真偽・教師の系統的共通誤りは別問題です。

循環小数になる文章題の答えは明示した分数形式で保持し、proofもその形式を再計算します。12桁へ丸めた値を厳密値と同一視しません。

混合時間と連続値引きでは、数値の集合ではなく出現番号を付けます。同じ30が速度と時間に2回出ても別tokenです。未知の追加数値、未解釈の価格操作、商品A/Bの切り替えは確定を阻止します。

## LLMの回答

claimごとの検算に加えて `answer_grounding.py` が原質問と回答全文の支持を確認します。既知の原質問の正答・適切な引用を限定形式で確認した場合だけ `verified` にします。無関係な正しい計算、正答の後へ追加された作り話、出典のない数値ではverifiedにしません。自由な文章全般の含意判定器は未実装です。任意の外部教師が正しいことも証明しません。

## 復元とファイルシステムの条件

生命・復元・署名・代謝の実装はV1022.5のままです。新しい配布bytesで独立process反復ゲートを回し、結果は外部の実測レポートに保存します。過去版の100回を今回の成績として流用しません。

今回のmanaged workspaceでは、旧版の第3世代チェックポイント復元が2回目に失敗しました。復元コマンドの終了時には公開projectionが一致し、次のprocessで未来のファイルが戻る観測があります。環境にはworkspaceを監視するinotifyとrsync daemonが存在し、調査中に `.rsync-tmp` の生成・消失も観測しました。外部同期干渉を示す証拠ですが、すべての再出現を特定のrsyncプロセスへ帰属させるOS syscall traceは取得できていません。

生きたdata rootは別writerや双方向同期が書き戻さないローカル領域に置いてください。稼働中のdata rootを同期対象にせず、停止して作ったZIP・チェックポイントの複製を同期します。この環境の `/tmp` は試験専用で、利用者の恒久保存先とはみなしません。同期workspace上の無人復元が解決したとは主張しません。通常の整合性検出は維持し、状態不一致を再署名して黙認する修正は行っていません。
