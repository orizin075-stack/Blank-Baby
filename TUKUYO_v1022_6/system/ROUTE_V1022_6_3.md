# V1022.6.3 仮説を見分ける有限研究

## 課題の形式

task.json:
```json
{"degree":2,"coefficient_values":[-1,0,1],"examples":[[0,0]],"target_x":2,"probe_costs":{"-1":1,"1":1,"2":10},"budget":3}
```

`y=c0+c1*x+c2*x*x`、各係数が-1/0/1の27候補を生成。x=0でy=0という経験に一致する9候補が残ります。目標は入力2の出力です。測れる入力と費用だけを渡し、正解や真の係数は渡しません。

```sh
python -B run_tukuyo.py --runtime-trust-file ../TUKUYO_v1022_6_3_TRUST_ANCHOR.txt --data /local/path/my_tukuyo hypothesis-research task.json
```

出力は入力-1を尋ねます。この例での最悪費用は2（-1と1を必要に応じて測る）で、目標2の直接観測10より少なくなります。events.jsonへ選ばれた観測だけを追加します。
```json
[{"x":"-1","y":0}]
```
```sh
python -B run_tukuyo.py --runtime-trust-file ../TUKUYO_v1022_6_3_TRUST_ANCHOR.txt --data /local/path/my_tukuyo hypothesis-research task.json --events events.json
```

候補3へ減り、次は入力1。観測 `{ "x":"1", "y":2 }` を追加すると、候補はy=x+x*xだけに絞られ、目標2の答え6で停止します。

入力-1の出力999なら全候補と矛盾するため `HYPOTHESIS_CLASS_FALSIFIED`、answer=nullです。仮説クラスを自動で広げる機能はありません。測定不能の場合は `{ "x":"-1", "error":"unavailable" }` とし、費用を計上して別入力へ再計画します。将来の測定失敗確率を織り込んだ最適化ではありません。

出力のproofをpacket.jsonへ保存し、`hypothesis-research-check packet.json` で独立検査できます。元課題とevents.jsonを渡す各呼出しは別processで再開できますが、履歴の保管は呼出し側の役割で、runtimeのSoul/Heart/Wholeへ研究を永続化していません。

## 判断の範囲

全候補が目標で同じ値を予測すれば `TARGET_AGREEMENT_WITHIN_CLASS` として答えます。全ての係数が一意である必要はありません。これは提供された有限クラスを前提にした推論です。実世界の答えとしての真偽を認証したという意味ではありません。

最悪費用は各観測出力の分岐について、次の最良質問を再帰的に選ぶBellman型探索で計算します。選択順は最悪総費用、現在の測定費用、入力値で確定します。費用が低くても残りが高額になる場合は最初の質問を避けます。情報を増やさない入力は選びません。予算内で目標を確定できなければ `NO_AFFORDABLE_DISCRIMINATION` で保留します。

別検査器は生成器を呼ばず、係数候補を別に列挙し、べき乗和で予測し、モデルindex集合と測定maskのmemoを使って全分岐を再計算します。元課題・履歴・選択・費用・候補・回答を束縛します。外部測定の真偽や暗号署名の認証は含みません。

degree 0〜2、係数集合1〜5個の整数（絶対値10以下）、最大125候補、初期生存候補32以下、examples1〜16、probes8以下、events8以下、入力絶対値100以下、費用1〜100、予算0〜800です。値は整数または正確な有理数文字列で最大128bit。探索は各decision5万state以内。限界到達は保留し、探索完了・最適性を主張しません。候補クラス・初期例・測定費用を後から変更すると同じ履歴を継続しているとは扱えません。
