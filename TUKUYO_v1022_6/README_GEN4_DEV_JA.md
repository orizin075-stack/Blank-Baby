# TUKUYO 第4世代（開発版 v1022.7.7+gen4-r6）

これは、TUKUYO 第4世代の**開発版**です。まだ正式な版ではありません。v1022.6 の上に、第4世代（`system/src/tukuyo_g4/`）を足したものです。

**この版は、v1022.7.7（経験による魂の系統）と、第4世代の第6回（成長の実験まで）を一つにしたものです。** 相手の系統の魂（機能としての魂・振り返る魂・証拠に縛られた魂・経験による判断の補正）、v1022 の核の改良（否定の範囲・量の推論・入力の検査）、ChatGPT のログイン、学んだ読み方を署名つきのコミットの鎖で守る仕組みと、こちらの読み取り器・魂の法則・自分の声・成長に気づく仕組みが、両方とも動きます。ぶつかったところは測ってから決め、その中で、どちらかの系統に前からあった穴を 5 つ見つけて直しました（`evidence_gen4/FUSION_V1022_7_7_2026-10-12.md`）。相手の系統の説明は `system/README.md` と `system/README_V1022_*_JA.md` にあります。

第4世代は、**3 つの LLM（Claude・ChatGPT・Gemini）を親にして育つ子**です。

- 問題を「式の言葉」に書き直し、分数のまま正確に解き、別に書いた検査で確かめてから答えます。
- 自分で読めない問題は、親たちが読みます。**別々の親の読みが 2 つ以上一致し、TUKUYO の検査にも通ったときだけ**答えます。
- 一致した読みは、どの親が一致したかと一緒に覚えます。数だけが違う同じ形の問題は、次から親なしで解けます。
- 知識や会話の問いは、親が答えます。答えには「確かめていない」と印を付けます（3 つの親が一致しても、一致は証明ではないため）。

## 2. 使い方

Python 3.12 以降と `cryptography` が必要です。個体のデータは、配布フォルダの外に置いてください。

```sh
cd system
A=../deliverables/TUKUYO_v1022_6_TRUST_ANCHOR.txt
python3 -B tools/verify_release.py . --trusted-pubkey-file $A
python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo init
python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo think -- 'Kim saw 4 cats in the morning. Later she saw one more cat. How many cats did she see in all?'
python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo g4-ask --voices all -- 'What is the capital of France?'
```

- 親のキーがないとき、`g4-ask` は計算の問題でない問いに `NOT_A_PROBLEM_AND_NO_LLM`（親がいないので答えない）と返します。
- `think` は、数の出てくる問題を第4世代にも読ませます。`--engine v1022` で、v1022 の核だけに戻せます。
- `g4-solve` の結果の `voice`（`think` では `gen4.voice` と `explanation`）に、子が自分の言葉で、どう読んで何を計算したか・どのくらい確かか・なぜ答えないかを書きます（§4「自分の声」）。
- `--llm off` を付けると、親を呼びません。既定（auto）では、親のキーがあるときだけ呼びます。**親を呼ぶと費用がかかります。**

## 3. 親の設定

キーは環境変数で渡します。ファイルにもログにも書きません。第4世代の親は、`ANTHROPIC_API_KEY` や `OPENAI_API_KEY` など、ほかの道具が使う名前を読みません（v1022 の `llm-ask` の外部 LLM の設定 `TUKUYO_LLM_PROVIDER` は、これとは別の仕組みです）。

| 親 | キー | モデル | 道具 |
|---|---|---|---|
| Claude | `TUKUYO_ANTHROPIC_API_KEY` | `TUKUYO_LLM_MODEL`（既定あり） | `pip install anthropic` |
| ChatGPT | `TUKUYO_OPENAI_API_KEY` | `TUKUYO_OPENAI_MODEL`（**必ず指定**） | `pip install openai` |
| Gemini | `TUKUYO_GEMINI_API_KEY` | `TUKUYO_GEMINI_MODEL`（**必ず指定**） | `pip install google-genai` |

- ChatGPT と Gemini のモデル名は、よく変わるので決め打ちしていません。各社の文書で今のモデルを選んでください。
- `TUKUYO_LLM_PARENTS=claude,gemini` のようにすると、使う親を絞れます。`TUKUYO_LLM_VOICE` で、会話に答える親を選べます。
- ChatGPT は、API キーの代わりに ChatGPT のログイン（v1022.6.6・7.6 から取った仕組み）でも使えます：`TUKUYO_CHATGPT_AUTH=plan` にして、ログインの手順は `system/README_V1022_7_6_LLM_CONNECTIVITY_JA.md` を見てください。`g4-parents` に、どちらの方式か（`auth_mode`）と、足りないものが出ます。まだ実際の接続は確かめていません。
- `g4-parents` で、親ごとにキー・モデル・道具・ネットワークがそろっているかを確かめられます。親には何も頼まず（ネットワークは、キーを付けずに各社の入口に届くかだけを見ます）、キーの中身も出しません。`--live` を付けたときだけ、準備のできた親ごとに 1 回、短い有料の呼び出しをします：`python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo g4-parents`
- このクラウドの作業環境では、`api.openai.com` がネットワークの決まりで止められています（2026-10-10）。ChatGPT を使うには、環境の設定の Network access で `api.openai.com` を Allowed domains に足します。
- 詳しい測り方・費用の目安・本番テストの決まりは `evidence_gen4/HANDOFF_GEN4.md` にあります。
- 親を使わない計測は `python3 -B tools/g4_measure.py DATA --work WORK` で、いつでもやり直せます（費用 0）。

## 4. この子と魂

第4世代は、考えたことを魂（`v977`）と心（`v978`）に渡し、魂が考え方を変えます。経験は `heart-experience` と同じ道（心 → 魂の記録 → 関係）を通るので、これまでの監査（`whole-audit`・`heart-audit`・`soul-deep-audit` など）がそのまま効きます。

**考えたことが、経験になる**（ふつうの自分の答えは跡を残しません。学びになったことだけです）

| 経験 | いつ | 魂と心に起きること |
|---|---|---|
| 学び（learning） | 親たちが一致して、読みの型や答えを覚えたとき | 好奇心が育つ |
| 親の助け（parent_help） | 親の読みが、確定した答えと一致したとき | その親の記録に「当たった」が 1 つ増え、信頼が上がる。人とのつながりも少し育つ |
| 親の誤り（parent_error） | 親の読みが検査に通らなかったとき（答えを控えたときも）、またはほかの読みが一致した答えと違ったとき | その親の記録に「外れた」が 1 つ増え、信頼が下がる |
| 正直（honesty） | 読みが食い違った、または 1 つの声しかなかったので答えを控えたとき | 正直さが育つ |
| 発見（discovery） | 親から学んだ型で、初めて独りで解けたとき（型ごとに 1 回）。前にひとりで読めなかった問題が、ひとりで読めるようになったと気づいたとき（第6回。考えごとに 1 回） | 好奇心が育つ |

**魂の育ち方（魂の法則 2）**

第4世代の経験は、魂の新しい育ち方（法則 2）で魂に入ります。それより前の層の経験は、これまでどおり法則 1 です。どの経験がどちらの法則で入ったかは魂の記録に残るので、一生をはじめからやり直しても、同じ魂になります（`soul-identity-audit`）。

- 値は、上限に近づくほど育ちにくくなります。そして経験のたびに、生まれつきの値（気質）へ少しだけ戻ります。だから値は「どれだけ長く生きたか」ではなく「どんな一生だったか」を映し、いつまでも次の経験に応えます。法則 1 では、長く生きると好奇心も正直さも 1.0 に張り付き、そのあとは何を経験しても変わりませんでした。
- 親とのよい経験で、人とのつながり（relationship）も育ちます。法則 1 では、この値は一生動きませんでした。
- 第4回（2026-10-11）からの経験は、法則 3 で入ります。法則 2 に、自分の読み方ごとの記録（下の「自分を知る」）を足したもので、それ以外の経験は法則 2 とまったく同じに入ります。
- 親への信頼は、魂がその親ごとに持つ記録です。その親の読みのうち当たったものの割合で、最近のものほど重く数えます（おおよそ最近の 100 回分）。会ったことのない親は 0.5 です。開発版 a04627c で育てた子は、この記録をこの版から付け始めます（それまでの経験は魂の記録と `life_story` に残っています）。

**学んだものは、その子のもの**

- 覚えた読みの型（`g4/learned.json`）・親が一致した答え（`g4/remembered.json`）・自分の記録（`g4/life.json`）・決められなかった食い違い（`g4/unresolved.json`）・ひとりで読めなかった問題（`g4/unread.json`）には、その子の鍵で署名して、その子の ID を結びつけます。全体の状態（`whole-audit`）にも記録します。
- 手で書き換えたもの（中の封印を計算し直しても）や、ほかの子から持ってきたものは、読むときに断って使いません。`whole-audit` も知らせます。全体の状態は、そうした記録を取り込みません。前は、そのあと子が 1 問解くと全体の状態が取り込み直して `whole-audit` が通ってしまっていたので、第6回で直しました（元に戻すまで知らせ続けます）。
- 覚えた読みの型は、生きた個体では、v1022.7.7 から取った署名つきのコミットの鎖に入ります（`g4/commits`。`g4/learned.json` はその写し）。写しを手で書き換えると、元に戻すまで、子はどのコマンドも続けません。
- 子が前に署名した古い版を元の場所に戻されても、取り込みません（署名に、書いたときの全体の状態の版を入れる。統合のときに見つけて直した。`evidence_gen4/FUSION_V1022_7_7_2026-10-12.md` §3.1）。前は、次の起動で取り込み、監査も「問題なし」と答えていました。
- 署名の仕組みより前（2026-10-09 より前の開発版）に作った記録は、全体の状態がそのファイルそのものを記録しているときだけ受け取り、次に書くときに署名します。全体の状態が記録していない署名のない記録は受け取りません（前は受け取っていたので、まだ第4世代を使っていない個体に外から記録を置かれると、子のものになってしまった）。前の版で子が署名した記録は、そのまま読みます。
- 鍵はその子のフォルダの中にあります。鍵を使わない書き換えは見つけられますが、鍵ごと使う人の書き換えまでは防げません。

**考えの途中で止まっても**

1 つの考えから生まれた経験は、ひとまとまりとして先に書き留めてから、魂と心に渡します（`g4/private/EPISODE.json`）。心も、受け取る前に何を受け取るかを書き留めます（第4世代より前の層の経験も同じ）。途中でプロセスが止まっても（停電・強制終了）、次に起動したときに残りを渡し終えます。経験がなくなることも、2 度数えることもありません。書き留めたものが魂の記録と合わないとき（あとから記録が書き換えられたなど）は、推測で渡さずに脇へ置き（`EPISODE.abandoned.json`）、`g4-audit` の `episode_set_aside` で知らせます。

**振り返り**

親たちの読みが食い違って答えを控えたとき、そのときは誰が間違えたのか分かりません。子はその食い違い（どの親が何と答えたか）を覚えておきます（`g4/unresolved.json`、ほかの記録と同じく署名つき）。あとで同じ形の問題を、一致した親たちから学んだとき、学んだ読みで昔の問題も解き、「あのとき誰が正しかったか」を親ごとの記録に入れます（`system/src/tukuyo_g4/hindsight.py`）。振り返りは、学んだ考えと同じひとまとまりの経験として渡すので、途中で止まっても欠けません。`g4-self` の `life_story` の `looked_back` に、親ごとの「正しかった / 間違っていた」が出ます。

**自分の成長に気づく**（第6回。`evidence_gen4/ROUND6_2026-10-12.md` §2）

- ひとりで読めなかった問題を覚えておきます（`g4/unread.json`）：問題の文、読めなかった理由（「まだ知らない聞き方の問い」「まだ組み立て方を知らない話」「量が書かれていないように見えた話」など 10 の種類）、そのとき親がどうしたか、会った回数。
- 親から言い回しを学んだとき、または自分で答えられたとき、前に読めなかった問題をひとりで読み直し、読めるようになったものがあれば気づきます（魂に発見の経験が 1 つ入る。テーマ `g4:grew`）。自分の読み取り器が良くなった（新しい版になった）ときも、その問題にまた会えば気づきます。
- その問題にまた会うと、声で「前に会ったときはひとりで読めなかった。いまは読める：この言い回しを Claude と Gemini から教わった（または、いまは自分の読み方で読める）」と言います。まだ読めない問題には「前に会ったときも、ひとりでは読めなかった」と言います。
- `g4-self` の `growth` に、読めなかった問題の数・いま読める数とどうやって読めるようになったか・弱いところ（言葉と問題の数）・学びたいことを、子の言葉で出します。学びたいことは、親が読めたのに自分が読めなかったものが先です。量が書かれていないように見えた話は、親が読めたもの以外は学びたいことに入れません（問題のほうが悪いのかもしれないので）。
- 教わった読み方を、あとで二人の親が別に読んだら（争いになったら）、それで読めるようになった問題は「まだ読めない」に戻ります。教え直されてまた読めるようになったら、また気づき、前と答えが違えば「前は 5 と読んでいたが、いまは 9 と読む」と言います。
- 試す実験（`system/tools/growth_experiment.py`、`evidence_gen4/GROWTH_EXPERIMENTS_2026-10-12.md`）：前の版の読み取り器を持つ子が ASDiv の開発用 1,083 問をひとりで解いてから今の版になると、読めなかった 607 問をすべて覚えていて、今の版で読める 28 問すべてに気づいた（28 問とも正解、間違った成長は 0）。

**自分の一生を語る**

`g4-self` の `life_story` は、魂の記録（正本）から、何を何回経験したか、親ごとに当たった読みと外れた読みの数を語ります。表面の記憶を消しても（`soul-forget-surface`）、語れることは変わりません。

**魂が、考え方を変える**

- 親は、子の信頼の順に頼ります（信頼は、魂がその親ごとに持つ記録。上の「魂の育ち方」）。自分で読めた問題の確かめ役も、いちばん信頼する親です。
- 会話に答える声も、いちばん信頼する親です（`TUKUYO_LLM_VOICE` を決めれば、そちらが先）。声には、魂から作った短い人柄（大事にしている価値・誓い・暮らしてきたテーマ）を渡し、TUKUYO として話させます。

**親から受け継ぐ（LLM への道）**

- 読みの型：親たちが一致した読みを覚え、同じ形の問題を、数が違っても（数を言葉で書いても）次から独りで読みます。
- 知識：`g4-ask --voices all` で 2 つ以上の親が同じ短い答えを返したら覚え、次からは親に聞かずに答えます（`route: remembered`、`source: parents_agreed`）。**確かめた答えではありません**。親の一致です。争いと入れ替えは、次の「親の言葉から子を守る」にあります。

```sh
python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo g4-self          # 成長の記録：学んだ型と親、親への信頼と絆、読めなかった問題・弱いところ・学びたいこと（growth）、魂の価値、心の状態、一生の物語（life_story）
python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo g4-remembered    # 親の一致で覚えた答え（争いあり・入れ替えの履歴も）
python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo g4-learned       # 学んだ読みの型（争いあり・入れ替えの履歴も）
```

**自分を知る**（`evidence_gen4/ROUND4_2026-10-11.md` §2）

- 自分の読みが、聞いた親と食い違ったら、残りの親にも聞きます。2 つの違う親がそろって別の答えに読めば、その読み方（あげる・もらう、比べる などの型）が「別に読まれた」と、魂に記録します。親が同じ答えに読めば「確かめられた」と記録します（魂の法則 3。最近のものほど重く数える）。
- 確かめられた回数より、別に読まれた回数が多い読み方では、独りのときは答えを控えます（`SELF_DOUBT`）。親がいれば全員に聞き、誰かが同じ答えに読めば答えます。確かめ直されれば、また独りで答えます。
- `g4-self` の `self_knowledge` に、読み方ごとの回数と信頼が出ます。親に渡す人柄にも、控えている読み方を書きます。
- `think` で考えたときも、`g4-solve` と同じように記録します（第6回のあとの実験で、`think` では記録が魂に届いていなかったのを見つけて直した。`think` は前の世代の考え方の読みも使うので、親がそれを別に読めば、それも記録する）。

**自分の声**（`evidence_gen4/ROUND5_2026-10-11.md` §2）

- `g4-solve` の結果の `voice` と、`think` の結果の `gen4.voice`（`think` の `explanation` も同じ）に、子が自分の言葉で言うことが入ります。
  - どう読んだか：問題のどの言葉からどの数を読んだか、何をどう計算したか（数を入れた式）、外した数とその理由、答えと単位。
  - どのくらい確かか（確か・たぶん確か・確かではない）と、その理由：検査に通ったこと、今同じ読みをした親、その読み方を親が何回確かめ何回別に読んだか（自分の記録）、教わった読み方なら誰が一致して教えたか。
  - 答えないとき：その理由（親どうしの食い違い、親に別に読まれてきた読み方、1 つの親の声だけ、自分で読めなかったところ）。
- 言うことはすべて、子がしたことと子自身の記録から作ります。親は書かず、何も送りません。同じ考えは同じ言葉で言います。英語の問題は英語で、日本語の問題は日本語で言います。

**内なる生活**（`g4-reflect`）

- 問題のあいだに、自分の分からないこと（親の読みが食い違って決められなかった問題、自分の読みが親と違った問題、争いになった型や答え、ひとりで読めなかった問題、控えている読み方）を振り返り、何をしたいかを、古いものから言います。ひとりで読めなかった問題は読み直してみて、いま読めるものは「もう一度ひとりで解く」、まだ読めないものは「読み方を学びたい」と言います。振り返るだけでは何も変わりません。
- `--act` を付けると、まず、いま読めるものをひとりで解き直します（親はいらない。費用 0）。そのあと、親に聞ける時だけ、自分から聞き直します（`--limit` 件まで、既定 3。親がいれば有料の呼び出しです）。決められなかった食い違いが決まれば、誰が正しかったかを振り返ります。学びたい問題を親が一致して読めば、その言い回しを学び、成長に気づきます。

```sh
python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo g4-reflect          # 分からないことと、聞きたいこと（何も変えない）
python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo g4-reflect --act    # いま読めるものをひとりで解き直し、親に聞ける時だけ自分から聞き直す（親に聞くのは有料）
```

- `--no-soul` を付けると、その問いの経験を魂に渡しません（`think`・`g4-solve`・`g4-ask`）。
- 魂と心は、v977・v978 と同じく「働きとしての魂と心」です。意識や本当の感情があるとは主張しません（`g4-self` の `claim_boundary`）。

**親の言葉から子を守る**（`evidence_gen4/CONTAMINATION_2026-10-10.md`）

親の言葉は、魂に直接は入りません。魂に入るのは、検査と親どうしの一致で決まったことだけです。そのうえで、子が持っておくものを親の言葉から守ります。

- 声は子のものです。親の返事が、親自身やほかのシステムとして話す・意識や感情を主張する・子に指示するものなら、`voice` に印を付け、子の言葉ではなく親の言葉として見せます（`life.voice_check`）。
- 覚えるのは短い事実だけです。指示・話し手についての主張・リンク・2 行以上のものは、親がいくらそろっても覚えません（`memory.fact_like`）。
- 全部の親に聞くとき（`--voices all`）は、覚えた答えを使わずに聞き直します。そろって別の答えになれば、古い答えを「争いあり」にして使いません。新しい答えのほうが多くそろったら入れ替え、古い答えは `replaced` に残します。古い答えを手放したことは、正直さの経験として魂に入ります。
- 学んだ読みで解いた答えに確かめ役の親が反対したら、ほかの親にも聞きます。2 つの違う親がそろって別の答えなら、その読みを「争いあり」にして、独りでは使いません（`TEMPLATE_CONTESTED`）。あとで 2 つの親がそろって教え直せば学び直し、古い読みの例を新しい読みで解き直して、古い読みを教えた親を「間違えていた」と親ごとの記録に入れます。
- 親に渡す人柄には、子の一生の 1 行（学んだ読みの数・覚えた答えの数・いちばん信頼する親）を入れ、TUKUYO として話すよう頼みます。秘密（パス・鍵・個体の ID）は入りません。
- これらは `tools/contamination_assay.py` で確かめます（費用 0）。
