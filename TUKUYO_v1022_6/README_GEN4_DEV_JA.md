# TUKUYO 第4世代（開発版 v1022.6+gen4-dev）

これは、TUKUYO 第4世代の**開発版**です。まだ正式な版ではありません。v1022.6 の上に、第4世代（`system/src/tukuyo_g4/`）を足したものです。

第4世代は、**3 つの LLM（Claude・ChatGPT・Gemini）を親にして育つ子**です。

- 問題を「式の言葉」に書き直し、分数のまま正確に解き、別に書いた検査で確かめてから答えます。
- 自分で読めない問題は、親たちが読みます。**別々の親の読みが 2 つ以上一致し、TUKUYO の検査にも通ったときだけ**答えます。
- 一致した読みは、どの親が一致したかと一緒に覚えます。数だけが違う同じ形の問題は、次から親なしで解けます。
- 知識や会話の問いは、親が答えます。答えには「確かめていない」と印を付けます（3 つの親が一致しても、一致は証明ではないため）。

## 2. 使い方

Python 3.12 以降と `cryptography` が必要です。個体のデータは、配布フォルダの外に置いてください。

```sh
cd system
A=../deliverables/TUKUYO_v1022_6_TRUST_ANCHOR.txt
python3 -B tools/verify_release.py . --trusted-pubkey-file $A
python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo init
python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo think -- 'Kim saw 4 cats in the morning. Later she saw one more cat. How many cats did she see in all?'
python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo g4-ask --voices all -- 'What is the capital of France?'
```

- 親のキーがないとき、`g4-ask` は計算の問題でない問いに `NOT_A_PROBLEM_AND_NO_LLM`（親がいないので答えない）と返します。
- `think` は、数の出てくる問題を第4世代にも読ませます。`--engine v1022` で、v1022 の核だけに戻せます。
- `--llm off` を付けると、親を呼びません。既定（auto）では、親のキーがあるときだけ呼びます。**親を呼ぶと費用がかかります。**

## 3. 親の設定

キーは環境変数で渡します。ファイルにもログにも書きません。第4世代の親は、`ANTHROPIC_API_KEY` や `OPENAI_API_KEY` など、ほかの道具が使う名前を読みません（v1022 の `llm-ask` の外部 LLM の設定 `TUKUYO_LLM_PROVIDER` は、これとは別の仕組みです）。

| 親 | キー | モデル | 道具 |
|---|---|---|---|
| Claude | `TUKUYO_ANTHROPIC_API_KEY` | `TUKUYO_LLM_MODEL`（既定あり） | `pip install anthropic` |
| ChatGPT | `TUKUYO_OPENAI_API_KEY` | `TUKUYO_OPENAI_MODEL`（**必ず指定**） | `pip install openai` |
| Gemini | `TUKUYO_GEMINI_API_KEY` | `TUKUYO_GEMINI_MODEL`（**必ず指定**） | `pip install google-genai` |

- ChatGPT と Gemini のモデル名は、よく変わるので決め打ちしていません。各社の文書で今のモデルを選んでください。
- `TUKUYO_LLM_PARENTS=claude,gemini` のようにすると、使う親を絞れます。`TUKUYO_LLM_VOICE` で、会話に答える親を選べます。
- 詳しい測り方・費用の目安・本番テストの決まりは `evidence_gen4/HANDOFF_GEN4.md` にあります。
- 親を使わない計測は `python3 -B tools/g4_measure.py DATA --work WORK` で、いつでもやり直せます（費用 0）。

## 4. この子と魂

第4世代は、考えたことを魂（`v977`）と心（`v978`）に渡し、魂が考え方を変えます。経験は `heart-experience` と同じ道（心 → 魂の記録 → 関係）を通るので、これまでの監査（`whole-audit`・`heart-audit`・`soul-deep-audit` など）がそのまま効きます。

**考えたことが、経験になる**（ふつうの自分の答えは跡を残しません。学びになったことだけです）

| 経験 | いつ | 魂と心に起きること |
|---|---|---|
| 学び（learning） | 親たちが一致して、読みの型や答えを覚えたとき | 好奇心が育つ |
| 親の助け（parent_help） | 親の読みが、確定した答えと一致したとき | その親の記録に「当たった」が 1 つ増え、信頼が上がる。人とのつながりも少し育つ |
| 親の誤り（parent_error） | 親の読みが検査に通らなかった、またはほかの読みが一致した答えと違ったとき | その親の記録に「外れた」が 1 つ増え、信頼が下がる |
| 正直（honesty） | 読みが食い違った、または 1 つの声しかなかったので答えを控えたとき | 正直さが育つ |
| 発見（discovery） | 親から学んだ型で、初めて独りで解けたとき（型ごとに 1 回） | 好奇心が育つ |

**魂の育ち方（魂の法則 2）**

第4世代の経験は、魂の新しい育ち方（法則 2）で魂に入ります。それより前の層の経験は、これまでどおり法則 1 です。どの経験がどちらの法則で入ったかは魂の記録に残るので、一生をはじめからやり直しても、同じ魂になります（`soul-identity-audit`）。

- 値は、上限に近づくほど育ちにくくなります。そして経験のたびに、生まれつきの値（気質）へ少しだけ戻ります。だから値は「どれだけ長く生きたか」ではなく「どんな一生だったか」を映し、いつまでも次の経験に応えます。法則 1 では、長く生きると好奇心も正直さも 1.0 に張り付き、そのあとは何を経験しても変わりませんでした。
- 親とのよい経験で、人とのつながり（relationship）も育ちます。法則 1 では、この値は一生動きませんでした。
- 親への信頼は、魂がその親ごとに持つ記録です。その親の読みのうち当たったものの割合で、最近のものほど重く数えます（おおよそ最近の 100 回分）。会ったことのない親は 0.5 です。開発版 a04627c で育てた子は、この記録をこの版から付け始めます（それまでの経験は魂の記録と `life_story` に残っています）。

**学んだものは、その子のもの**

- 覚えた読みの型（`g4/learned.json`）・親が一致した答え（`g4/remembered.json`）・自分の記録（`g4/life.json`）には、その子の鍵で署名して、その子の ID を結びつけます。全体の状態（`whole-audit`）にも記録します。
- 手で書き換えたもの（中の封印を計算し直しても）や、ほかの子から持ってきたものは、読むときに断って使いません。`whole-audit` も知らせます。
- 署名の仕組みより前に作った記録は、全体の状態がほかの版を記録していなければ受け取り、次に書くときに署名します。
- 鍵はその子のフォルダの中にあります。鍵を使わない書き換えは見つけられますが、鍵ごと使う人の書き換えまでは防げません。

**考えの途中で止まっても**

1 つの考えから生まれた経験は、ひとまとまりとして先に書き留めてから、魂と心に渡します（`g4/private/EPISODE.json`）。心も、受け取る前に何を受け取るかを書き留めます（第4世代より前の層の経験も同じ）。途中でプロセスが止まっても（停電・強制終了）、次に起動したときに残りを渡し終えます。経験がなくなることも、2 度数えることもありません。書き留めたものが魂の記録と合わないとき（あとから記録が書き換えられたなど）は、推測で渡さずに脇へ置き（`EPISODE.abandoned.json`）、`g4-audit` の `episode_set_aside` で知らせます。

**自分の一生を語る**

`g4-self` の `life_story` は、魂の記録（正本）から、何を何回経験したか、親ごとに当たった読みと外れた読みの数を語ります。表面の記憶を消しても（`soul-forget-surface`）、語れることは変わりません。

**魂が、考え方を変える**

- 親は、子の信頼の順に頼ります（信頼は、魂がその親ごとに持つ記録。上の「魂の育ち方」）。自分で読めた問題の確かめ役も、いちばん信頼する親です。
- 会話に答える声も、いちばん信頼する親です（`TUKUYO_LLM_VOICE` を決めれば、そちらが先）。声には、魂から作った短い人柄（大事にしている価値・誓い・暮らしてきたテーマ）を渡し、TUKUYO として話させます。

**親から受け継ぐ（LLM への道）**

- 読みの型：親たちが一致した読みを覚え、同じ形の問題を、数が違っても（数を言葉で書いても）次から独りで読みます。
- 知識：`g4-ask --voices all` で 2 つ以上の親が同じ短い答えを返したら覚え、次からは親に聞かずに答えます（`route: remembered`、`source: parents_agreed`）。**確かめた答えではありません**。親の一致です。あとで親たちが別の答えで一致したら「争いあり」として使いません。

```sh
python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo g4-self          # 成長の記録：学んだ型と親、親への信頼と絆、魂の価値、心の状態、一生の物語（life_story）
python3 -B run_tukuyo.py --runtime-trust-file $A --data ~/tukuyo g4-remembered    # 親の一致で覚えた答え
```

- `--no-soul` を付けると、その問いの経験を魂に渡しません（`think`・`g4-solve`・`g4-ask`）。
- 魂と心は、v977・v978 と同じく「働きとしての魂と心」です。意識や本当の感情があるとは主張しません（`g4-self` の `claim_boundary`）。

**魂らしさの試験**

`tools/soul_assay.py` で、新しい子を作って 7 つの性質を確かめます（親は記録した返事、費用 0）：連続性・強制終了からの復元・表面の記憶を消したあとの深い自分・個性・長い一生・改ざん・自分の一生を語ること。改良前（a04627c）は連続性と個性の 2 つだけ合格、改良後は 7 つすべて合格です。結果と、まだ残っていること：`evidence_gen4/SOUL_ASSAY_2026-10-09.md`。
