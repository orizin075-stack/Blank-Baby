# V1022.6.2 有限観測研究ルート

## 入力と操作

例: `制約: A+B=10。Aは何？`。測れるのはA（費用4）とB（費用1）、予算5です。候補の質問や数値の正解を教えず、測定能力だけを渡します。

capabilities.json:
```json
{"budget":5,"measurements":{"A":4,"B":1}}
```

```sh
python -B run_tukuyo.py --runtime-trust-file ../TUKUYO_v1022_6_2_TRUST_ANCHOR.txt --data /local/path/my_tukuyo think '制約: A+B=10。Aは何？' --research-capabilities capabilities.json
```

結果は `AWAITING_OBSERVATION`、質問 `Bは何？`、費用1。Bの値を実際の測定者が得た後にevents.jsonへ追加します。
```json
[{"variable":"B","value":"3"}]
```
```sh
python -B run_tukuyo.py --runtime-trust-file ../TUKUYO_v1022_6_2_TRUST_ANCHOR.txt --data /local/path/my_tukuyo think '制約: A+B=10。Aは何？' --research-capabilities capabilities.json --research-events events.json
```

結果は `GOAL_ESTABLISHED`、A=7、費用1。Bを測れなかった場合は `[{"variable":"B","error":"unavailable"}]` とします。費用1を計上し、残り4でAの測定へ切り替えます。失敗した測定も無料にはしません。予算4ならB失敗後のA測定は不可能なので `NO_AFFORDABLE_RESEARCH` と保留します。

`A+B+C=20。Aは何？` でA=費用8、B=2、C=3ならB、次にCを選び、計5でAを導きます。Bだけでは確定しません。目標が既知なら測定しません。

各呼出しは元のquery/capabilities/eventsから再構築するため、別processで続けられます。ただしevents.jsonの保管は呼出し元の役割です。runtimeのSoul/Heart/Wholeに研究履歴を追記する機能はありません。proof（出力JSONのproofフィールド）をpacket.jsonへ保存して `research-check packet.json` で独立検査できます。packetや元の外部測定値が暗号署名されているという主張はありません。

## 選択と検証

最大8センサーから最大256部分集合を列挙します。目標の値を一意にする集合を最小総費用、最少測定数、辞書順で選び、その集合の中の費用最小の測定を一つ質問します。値が返る前に次の質問を選択し、返った値はその後の計画にだけ適用します。利用不可センサーは以降除外します。

独立検査は生成器を呼ばず、別の字句parserで元条件と追加条件を読み、零空間で目標の一意性、全安価な代替、費用、選択順、履歴束縛、終端回答の証明を確認します。外部入力の正しさ、統計的独立性、一般言語の意味理解はこの検査の範囲外です。

入力は `budget` 0〜800、各センサー費用1〜100、元式に宣言された変数だけです。値は整数または有理数文字列、最大160bit。型付き整数数量、非線形、未知センサー、候補に値を埋め込む入力、選ばれていない値、終端後の余分な観測、再観測は拒否します。元式＋最大追加式は32、eventsは8までです。

## 合格条件と未達

前版531テストを保持、新規の生成質問・部分観測・失敗切替・費用・改ざん・別checkerを検証し、通常CLIの外部模擬観測で連続研究を再現することを今回のゲートとします。一般AGIや点数を合格条件にはしません。

現実ツール、自由な仮説/新変数生成、対話での技能学習、runtime内部の永続研究記憶、代謝への研究成果接続、24h、新規100回restoreは未達です。workspace復元時の未来ファイル再出現問題は解決を主張しません。意識・文字通りの魂は評価対象にしていません。
